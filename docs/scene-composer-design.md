# Scene Composer Design (blscene)

Goal: programmatically create a new Bannerlord scene (battle / village / town) from
existing sources — reusing prefabs from any module, copying entities from existing
scenes, generating terrain — without the in-game editor.

**Target game version: v1.4** — all reference files/paths come from
`D:\SteamLibrary\steamapps\common\Mount & Blade II Bannerlord` (the v1.4 install).
Formats verified identical to the v1.2 files used in the initial recon
(xscene version="2", ZGR6RTRN terrain magic).

## Verified format facts (2026-07-13 recon)

- `scene.xscene` is plain XML (tab-indented, `%.3f` floats). Root `<scene name version="2">`:
  `flora_bounding_rect`, `levels` (base/level_1/2/3/siege/civilian, bitmasks),
  `environment_properties` (+ atmosphere/water/oob sub-blocks), `<entities>` of
  `<game_entity prefab="...">` (transform + optional levels/tags/scripts/children),
  `<terrain>` node (node_dimension_x/y, node_size, min/max_height, layer config).
- Prefab definitions: `<Module>/Prefabs/*.xml`, root `<prefabs>`, same `game_entity`
  schema as scenes. Scenes reference them by name; engine resolves across active modules.
- `terrain.bin`: ZGR6 container (see `blnav/terrain.py`), 5 sections MIDX/HGHT/NRML/WGHT/PHYM,
  LZ4 raw streams; HGHT = 129x129 16-bit PNG nodes, 1px overlap.
- `SceneEditData/<scene>/terrain_ed.bin`: editor-only source data; NOT required at runtime
  (runtime reads SceneObj only). Composer may skip it (scene won't be terrain-editable in
  the official editor until we also write it — acceptable v1 limitation, verify in-game).
- `flora.bin` empty stub = `FLR2` `04 00 00 00` `00 00 00 00` (12 bytes, Coventry ships this).
- `references.txt`: first line = count, then `mesh <name>` lines (asset preload manifest).
  Generate from the meshes of placed prefabs (walk prefab XML meta_mesh_components).
- `atmosphere.xml`: flat `<atmosphere><values>` list — copy from a template scene.
- `navmesh.bin`: RNM1/NMG9 — generator already exists (`blnav.generate` + MCP tools).
- ShaderCache: generated by the game; omit.

## Scene loading / registration (verified)

- Engine finds a scene by folder name in any active module's `SceneObj/` — no XML needed
  to load a mission scene programmatically.
- Custom Battle menu list (`CustomGame.LoadCustomBattleScenes`): easiest in-game validation.
  v1.4 format — ModuleData/custom_battle_scenes.xml:
  `<CustomBattleScenes><Scene id="<SceneObj folder>" name="{=key}Label" terrain="Plain"/></CustomBattleScenes>`
  registered in SubModule.xml via `<XmlNode><XmlName id="CustomBattleScenes" path="custom_battle_scenes"/></XmlNode>`.
  Optional attrs per CustomBattleSceneData: forest density, is_siege_map, is_village_map,
  is_lords_hall_map, terrain_types list.
- Campaign wiring: settlements reference scene names in settlements XML; battle terrain
  mapping via battle_scenes XML (not needed for v1 validation).

## Scene-type minimum requirements

- Battle (verified against v1.4 battle_terrain_a, 159 KB xscene, 82 entities, ZERO prefab
  refs — all inline): terrain + flora stub + navmesh + these inline entity groups:
  `border_soft`/`border_1`/`barrier_path_*` (map edges), `sp_battle_set` (spawn hierarchy),
  `sp_{attacker,defender}_{archer,cavalry,horsearcher,infantry}_reinforcement`,
  TacticalPosition/TacticalRegion script entities, AmbientSoundEmitter, ReflectionCapturer.
  Composer battle template: copy the sp_battle_set subtree + borders from a native battle
  scene and reposition to the generated terrain (this is the "reuse existing sources" path).
- Village: navmesh + sp_player_outside / sp_player, npc spawn points, passages.
- Town: as village + gates/castle entities; siege adds wall_segment tags + siege levels.
- Level semantics: entity shows only when mission includes ALL its assigned levels.

## Components (build order)

1. `blscene/xscene.py` — Scene load/modify/save, byte-identical round-trip (agent, in progress)
2. `blscene/prefabs.py` — PrefabCatalog scan of Modules/*/Prefabs (agent, in progress)
3. `blnav/terrain_write.py` — ZGR6 writer + generate_terrain(heightmap) (agent, in progress)
4. `blscene/compose.py` — the composer (next):
   - `SceneBuilder(name)` — start from a minimal template xscene (levels, env props,
     terrain node) or `SceneBuilder.from_scene(path)` to clone an existing scene.
   - `.set_terrain(heights, node_size, ...)` → terrain node attrs + terrain.bin
   - `.add(prefab, pos, rot, levels=...)` with PrefabCatalog validation
   - `.copy_entities(src_scene, filter)` — reuse chunks of existing scenes
   - `.build(out_dir)` → SceneObj/<name>/ with scene.xscene, terrain.bin, flora.bin,
     atmosphere.xml, references.txt, navmesh.bin (via blnav.generate on the heightmap,
     then per-spawn-point coverage check)
   - battle/village templates seeding required spawn-point entities per scene type
5. MCP tools in `server/mcp_server.py` wrapping the composer (after 4 validated).
6. In-game validation: register test scene in a module + CustomBattleScenes entry,
   launch via GABS, confirm load + walkable navmesh.
